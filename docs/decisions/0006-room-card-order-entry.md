# ADR-0006: 房间卡作为开单入口

- 状态：已接受（2026-11-23）
- 决策问题：值班人员看到房间卡后要能立刻为这间房开单，而不是先去订单列表再回头选房间
- 影响范围：`HomePage` 房间卡可点击、新增 `OrderEntryModal`、`ordersApi` 补齐建单 / 明细 / 提交 / 收款、`utils/money` 增加定点运算助手；修订 [ADR-0005](0005-home-overview.md) §3 的「首页只读」边界

## 背景

[ADR-0005](0005-home-overview.md) 把首页定为纯只读总览，理由是「同一动作不要在首页和专用页各有一套写逻辑」。这个边界对队列成员与房间维护成立：它们各有唯一编辑页，首页重复一套只会制造两条失效路径。

但「为这间房开单」不同：它的**上下文就是房间本身**，而首页恰好是唯一按房间铺开的地方。要求用户先点进 `/orders`、再在弹窗里从下拉里找回刚才看到的房间，是把已知信息丢掉再让用户重填一遍。截至本 ADR，前端也**完全没有建单入口**——`ordersApi` 只有列表、详情与 ADR-0022 的卡 / 房间绑定，后端 `POST /orders` 与明细、提交、收款端点齐备却无人调用。

## 决策

1. **房间卡就是开单入口**。启用中的房间卡可点击（`role="button"`、`Tab` 可达、`Enter` / `Space` 触发），点击弹出「开单」弹窗并把该房间预填进去。不新增 `/orders/new` 工作台路由：开单需要房间上下文，独立页面要么再选一次房间，要么把房间塞进 URL 参数，两种都比弹窗多一步。
2. **不可开单的房间保持惰性并说明原因**。停用房间不响应点击、卡上直接写「房间已停用，不能开单」——后端对停用房间返回 `409 ROOM_INACTIVE`，与其让用户填完明细才失败，不如在入口处就说清。没有 `order.write` 时同样不可点，提示「没有开单权限」。
3. **弹窗只做开单必需的四件事**：房间（预填、仅列启用房间、可改）、ID 卡（必选，仅列「生效 + 已有人持有 + 未被其他活跃订单占用」）、明细（目录项加入购物车、数量可改、可删）、提交。ADR-0022 的房间绑定在这里是**归因不是锁**：弹窗明说「同一房间可同时挂多张订单，分开买单各自收款」，合并买单要去订单详情建同行组。
4. **总价以服务端快照为准，前端估算只用于显示**。提交是「建单 → 逐条加明细 → 回读订单取 `lines[].amount` 求和 → `submit`」，传给 `total_amount` 的是**回读的服务端快照之和**，不是上面的「预计合计」。原因：`SubmitOrder` 用 `money.Money` 逐行重算并要求与客户端金额**字符串严格相等**，前端用浮点或多算一位小数都会被 `422` 拒掉；而单价本来就由服务端从目录项快照，客户端无权定价。
5. **提交成功后可直接收款，也可稍后收款**。收款只提供 `cash` / `card` 两个渠道（schema `CHECK` 允许的 `balance` 需要会员账户，本页没有会员上下文，不提供即不误导）。一次点击收全额；收款会在同一事务内释放该单的卡绑定与人员持卡（ADR-0022 §4），弹窗提示「已收款，ID 卡已自动释放」。
6. **部分失败不退回表单，而是交还草稿**。建单成功但加明细或提交失败时，草稿已占用这张卡和这间房，让用户就地重试必然撞 `CARD_BOUND_TO_ORDER`。此时弹窗切到「开单未完成」面板：显示真实原因、单号、房间、卡，并给出「去订单列表」与「关闭」；不再保留一个注定失败的提交按钮。
7. **只读边界按此收窄，其余不变**。ADR-0005 §3 的「首页没有任何写操作」改为「首页唯一的写入口是房间卡开单弹窗；队列与房间内容仍只读」。首页依然不新增后端端点、不新增权限：复用 `POST /orders`、`/orders/{id}/lines`、`/orders/{id}/submit`、`/orders/{id}/payments`，全部经共享 client 带 `X-Shop-Id` 与自动幂等键。

## 备选方案（不采用）

- **新建 `/orders/new` 收银工作台整页**（`porch-os` design/16 的 8 区域：房间上下文、明细编辑、试价、折扣、收款、同行组）：工作量与决策面都大得多，且其中多数区域（折扣、会员、拆并单）本期无对应前端权限与数据；先做房间入口这一条最短闭环，整页另立 ADR。
- **点房间直接创建空单**：会留下一批无明细草稿，且卡与房间已被占用，用户还得回头补明细——比多一步弹窗更糟。
- **弹窗内自行计算总价并提交**：见决策 4，会被金额严格相等校验拒绝，长期还会在折扣、调整项加入后与后端口径分叉。
- **允许停用房间开单**：后端按设计拒绝，前端放行只是把 `409` 推迟到用户填完明细之后。

## 影响

- `ordersApi` 新增 `create` / `addLine` / `removeLine` / `submit` / `pay`；类型新增 `PaymentEntry`、`Payment`、`PaymentResult`。
- `utils/money` 新增 `lineAmount` 与 `sumAmounts`（`decimal.js`），金额运算不走浮点（ADR-0004）。
- 首页 `PageHeader` 描述由「数据全部来自服务端，本页只读」改为「点击启用中的房间可直接开单，其余内容只读」。
- 开单弹窗是**首个**调用订单写端点的前端界面；订单列表仍只读（详情抽屉可绑卡 / 绑房 / 建同行组），完整收银工作台、折扣、会员、退款界面仍属后续阶段。
