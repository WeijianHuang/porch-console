# ADR-0003: 房间管理与楼层分组视图

- 状态：已接受（2026-11-19）
- 决策问题：新增「房间管理」页面，按**楼层分区**维护门店房间，对齐后端 [ADR-0011](https://github.com/WeijianHuang/porch-os/blob/main/docs/decisions/0011-rooms-and-floors.md) 的房间与楼层契约
- 影响范围：路由表（`App.tsx`）、侧边栏（`AppShell.tsx`）、API 类型 / `api/rooms.ts` / query keys、房间页（`RoomsPage.tsx`）、纯函数 `shop/roomGroup.ts` 与单测、`styles.css`；不改变认证、门店上下文、幂等与缓存失效协议（ADR-0001）

## 背景

用户要求「添加房间功能，房间需要区分楼层」。后端已由 porch-os ADR-0011 固化领域契约：房间归属单一门店，房间号 `(shop_id, code)` 店内唯一，`floor` 是房间上的整数属性（`-5..200`，负数表示地下），不是独立实体；列表按 `floor, code` 升序返回。本仓记录前端侧对应的页面与「区分楼层」的呈现决策。

## 决策

1. **导航与路由**：侧边栏在服务人员之后新增「房间管理」（第三人称图标 `ApartmentOutlined`），路由 `/rooms`；菜单选中逻辑按路径前缀 `/rooms` 命中。主页默认视图（`/queues`）不变。

2. **房间页**：按 `currentShopId` 拉取 `GET /shops/{id}/rooms`，得到扁平列表后由**纯函数 `groupByFloor`** 按楼层分组——楼层降序（高楼层在前、地下在后），组内按房间号升序；每个楼层分区是一个卡片面板，带楼层徽标（`floorLabel`：`1`→`1F`、`0`→`GF`、`-1`→`B1`）与房间数。房间以小卡片呈现房间号、名称、启用 / 停用状态；停用房间保留在列表中但弱化显示，不隐藏。

3. **写操作**：`POST /rooms` 新建（楼层 + 房间号 + 名称）、`PATCH /rooms/{id}` 编辑 / 启停（带 `version`）、`DELETE /rooms/{id}` 删除（二次确认）；楼层用数字输入并做 `-5..200` 前端校验，房间号与名称必填。写权限由 `room.write` 控制，只读用户看不到新建 / 编辑 / 启停 / 删除入口。409 版本冲突与错误码提示沿用统一 `ApiError` 呈现。

4. **楼层是展示分组**：楼层清单完全由当前门店房间的 `floor` 值推导，**无楼层 CRUD 端点、无 `floor_id`、无楼层选择下拉**；`floorLabel` 只影响展示，不回写后端。分组 / 格式化是纯函数（`src/shop/roomGroup.ts`），可脱库单测，符合 DA-01「折叠逻辑放纯函数」。

5. **单店上下文不变**：所有房间端点经统一 client 带 `X-Shop-Id`，写操作带 `Idempotency-Key`；query key 含 `current_shop_id`（`queryKeys.rooms`），切换门店走既有「取消在途 + 失效 shop-scope 缓存 + 重拉权限」协议。新建 / 编辑 / 启停 / 删除后只失效本店 `rooms` 查询键。

6. **不引入的呈现**：不做房间占用 / 预订状态、楼层平面图、按楼层统计看板、房间与队列 / 人员的关联入口——与后端 ADR-0011 的「不引入」边界一致。

## 理由

- 「区分楼层」由纯函数分组完成，后端保持扁平 DTO，符合 SQL 优先、无实体图（ADR-0002）。
- 楼层用数字输入与 `-5..200` 校验，与后端 `ck_rooms_floor` 一致，双向约束避免无效数据。
- 复用既有 `PageHeader`、统计条、卡片网格与 `pill` 状态样式，房间页与既有业务页视觉统一，不新增设计系统分支。
- 复用既有单店上下文与缓存失效协议，房间作为普通 B 类门店资源接入，不改变任何横切机制。

## 后果与限制

- 楼层顺序固定为降序，暂不支持用户自定义楼层排序或折叠空楼层（无房间即不显示该层）。
- 房间号门店内唯一；前端新建时若房间号重复，由后端 `409 CONFLICT` 兜底并提示。
- schema 版本由 `5` 升为 `6`，需先执行 porch-os `cmd/job migrate` 再使用本页。
- 公开仓库脱钩约束不变：只用 `room` / `floor` / `code` 等通用词。
