# ADR-0005: 首页概览（调度队列 + 房间）

- 状态：已接受（2026-11-23）
- 决策问题：登录后需要一个总览入口，同时看到调度队列与房间状态，而不是直接落在某个编辑页
- 影响范围：新增 `/home` 路由与侧栏首项；默认落地页由 `/queues` 改为 `/home`；新增 `HomePage` 与首页样式；更新 README / CHANGELOG

## 背景

[ADR-0002](0002-queues-default-view.md) 把登录后落地页定为 `/queues`，当时 R1 只有队列与服务人员，队列页就是全部内容。此后房间（ADR-0003）、调度台（ADR-0004）、ID 卡与订单陆续并入，控制台的第一屏却仍是「编辑队列成员」这个具体动作的页面：值班人员登录后想先知道「有哪些队列、各自谁在列、房间是什么状态」，需要先看队列页再跳到房间页。

## 决策

1. **路由与导航**：新增 `/home`，侧栏第一项为「首页」（`HomeOutlined`）。`/` 与登录后重定向到 `/home`。本 ADR 取代 ADR-0002 中「默认路由为 `/queues`」这一条，其余决策（队列页的视图、分配、排序协议）不变；ADR-0003 / ADR-0004 中「不改变默认落地页」的表述随之失效。
2. **内容两块**：
   - **调度看板队列**：每个队列一张横向卡片，含序号、名称、启用 / 停用、按位次排序的成员姓名（前 6 位，其余折叠为「+N」；圆点区分在岗 / 离岗）、在列人数，底部「查看队列」进入 `/queues`。
   - **房间**：所有房间卡片包在**同一个面板块**内，卡片横向排列（`flex-wrap`），每张显示房间名称、房号、楼层、启用 / 停用；停用房间降透明度但**不隐藏**——值班需要知道它存在且当前不可用。
3. **只读**：首页没有任何写操作，也不新增后端端点。数据来自 `GET /queues` + 每条 `GET /queues/{id}` 与 `GET /rooms`，全部经共享 client 带 `X-Shop-Id`；query key 复用 `queues` / `queue` / `rooms`，门店切换按既有协议统一失效，不新增缓存层。**本条已被 [ADR-0006](0006-room-card-order-entry.md) 收窄**：首页唯一写入口是「点击房间开单」，队列与房间内容仍只读。
4. **用队列详情而不是 `GET /scheduling/board`**：调度看板端点要求 `scheduling.read`，而首页应对只有 `queue.read` 的角色同样可用；队列详情已经给出成员与位次，足以表达「调度看板里的队列」。置顶、冻结、派单、判定链等能力仍只存在于 `/board`，首页不复制。
5. **横向排列用 `flex-wrap` 而非固定列网格**：队列 0–N 条、房间数量不定，固定网格在少量卡片时留下空洞、在大量卡片时挤压或横向滚动。1440 与 1024 宽实测无横向溢出。
6. **术语**：沿用通用文案（队列 / 服务人员 / 房间 / 楼层 / 位次），敏感词扫描零命中。

## 备选方案（不采用）

- **直接复用调度看板页面作为首页**：需要 `scheduling.read`，且首屏被密度切换、事件表、派单按钮占满，不是总览。
- **首页可编辑（勾选队列成员、启停房间）**：会让同一动作在首页与队列页 / 房间页各有一套写逻辑与失效路径，违背「写入口单一」。
- **保留 `/queues` 为默认页，首页只作可选菜单**：与用户提出的「新增首页菜单」不符，登录后仍需多点一次才能看到全貌。

## 影响

- 新增受保护路由 `/home`；ADR-0002 的默认路由部分被取代，其余内容继续有效。
- 队列页仍是队列成员编辑的唯一入口；房间页仍是房间维护的唯一入口，首页只做投影。
- 首页不引入新的权限：队列部分依赖 `queue.read`（与队列页一致），房间部分只要求门店授权（后端房间读端点不额外校权限）。
