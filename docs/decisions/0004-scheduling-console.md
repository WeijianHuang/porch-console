# ADR-0004: 调度台并入本前端

- 状态：已接受（2026-11-20）
- 决策问题：后端将多队列调度规则引擎整合进 porch-os（后端 ADR-0012）后，前端如何承载引擎的调度台界面
- 影响范围：新增 `/board`、`/rules`、`/linkage`、`/audit` 四页与侧栏入口；新增 scheduling API / 类型 / query keys；更新 README / CHANGELOG

## 背景

一个独立的多队列调度规则引擎已按 PRD 完成纯 Go 库。业务确认它本就是站点队列使用的引擎，应并入 porch-os，不再是独立项目；前端也相应并入本仓库，而不是新建独立前端。

## 决策

1. **同仓承载**：调度台作为本应用的四个新路由与导航项，复用既有站点切换器、森林绿设计系统、`X-Shop-Id` 请求上下文与 401 刷新流程。不新建独立前端工程。
2. **服务端为真源**：前端只持有 UI 过滤状态；所有位次、执行者状态、判定链、联动策略、决策与审计都来自服务端读取。所有变更走写端点（带自动幂等键）。这样与 ADR-0012 的「一次事件一次决策、单事务、审计单一来源」一致。
3. **四页面**：
   - `/board` 调度看板：队列**竖向排列**（一条队列一行，成员为换行网格，见决策 6）、执行者位次卡（状态色标 + 文字、主队列 / 置顶标记）、派单抽屉（≤3 步）、置顶 / 解除、回原位 / 完成 / 取消、决策解释抽屉。
   - `/rules` 判定链配置：8 步顺序 / 开关 / 作用域 / 命中动作 / 时段可编辑，发布新版本。
   - `/linkage` 联动策略：六种模式、名单 / 排除、逐队列动作映射，突出「各自落位」。
   - `/audit` 审计与指标：append-only 审计流水；指标只展示实测计数 / 比例，不设目标阈值。
4. **站点切换失效**：全部调度 query key 都含 `shop-scope` 前缀与当前 `shopId`（`queryKeys.scheduling*`），切换站点时由既有切换协议统一失效，避免跨站点数据残留（ADR-0006）。
5. **术语合规**：所有 UI 文案、类型名、注释只用通用术语（站点 / 执行者 / 位次 / 指派方式 / 判定链 / 调度看板等）。敏感词对照表本体不入仓库，新增内容需通过敏感词扫描零命中。
6. **看板布局与密度（2026-11-20 补充）**：单队列执行者可达 20 人，原「队列并排 + 列内竖向堆卡」会把页面拉到两千多像素，同时把其他队列挤到需要横向滚动。调整为：
   - **队列竖向排列**：`.board-lanes` 改为纵向 flex，一条队列占一整行（左侧 3px 色条 + 队列头 + 成员网格），与队列看板矩阵视图的分组方式一致，多条队列自上而下阅读。
   - **成员换行网格**：`.lane-members` 用 `grid-template-columns: repeat(auto-fill, minmax(var(--card-min), 1fr))`，列宽、间距、内边距全部来自密度变量，20 人自动折行，不再横向滚动。
   - **三档密度切换**：工具栏「卡片密度」提供 `紧凑 / 中度 / 宽松`（1440 宽下分别 7 / 5 / 4 列，卡片约 152 / 213 / 266px）；紧凑档额外隐藏「主队列 / 置顶」文字标签，改为绿色圆点与金色位次角标，置顶操作按钮降到 50% 不透明度、悬停恢复。密度只改尺寸与装饰，**不减少信息字段**（位次、姓名、状态、工号始终可见）。
   - **纯前端偏好**：密度存在 `localStorage: porch-console:board-density`（`src/stores/boardDensity.ts`，未知值回落「中度」），不写入服务端、不进 JWT、不影响位次与调度结果；切换站点不重置。
   - 事件表操作列不再 `fixed: 'right'`：窄屏下固定列会占满整行宽度、把其余列挤出可视区，改为普通列随表横向滚动。

## 备选方案（不采用）

- **独立前端仓库**：与「并入 porch-os」的业务确认冲突，且会重复实现站点切换与会话流程。
- **前端内存态模拟引擎**：会让审计与位次脱离服务端单一真源，与后端 ADR-0012 的事务 / 幂等 / 审计契约不符。

## 影响

与 ADR-0001（技术栈）、ADR-0002（默认视图）、ADR-0003（房间页）一致；不改变默认落地页（仍为 `/queues`）。新增页面均为受保护路由。
